
## Interview 1 – Anonymous | College Student | Coding & Project User

Direct Quotes:
- "I use Claude mainly for coding and project work."
- "The most frustrating problem is chat limits."
- "When limits end, I usually wait for the renewal period."
- "The seriousness depends on the type of task I'm doing."
- "The biggest impact is time waste."
- "If a tool solved this problem, I would use it — especially if it's free."
- "For a student plan, ₹99 would be acceptable."
- "Ideal solution: free chat limits for students."

Most Surprising Thing:
The user did not ask for more AI features or better model quality. Their main concern was uninterrupted access during coding and project work.

What It Changed About My Design:
Initially, I focused on adding more AI capabilities. After this conversation, I shifted toward affordability, student-friendly pricing, and minimizing workflow interruptions.

## Interview 2 – Student | GitHub Copilot User

Direct Quotes:
- "I mainly use GitHub Copilot."
- "Sometimes it auto-changes code and makes it complex to understand."
- "My current workaround is spending 1–2 hours understanding or fixing it."
- "Seriousness level: 7/10."
- "I would definitely use a solution for this problem."
- "I prefer a free solution."
- "Ideal solution: show before vs after comparison."

Most Surprising Thing:
The frustration was not wrong code generation. The real issue was understanding unexpected AI changes and losing clarity in their own code.

What It Changed About My Design:
Initially, I focused on improving code generation speed. This conversation pushed me toward explainability, visual code comparisons, and transparent AI changes.

## Interview 3 – Student | Codex User

Direct Quotes:
- "I use Codex."
- "The most frustrating part is explaining the same thing again and again."
- "My current workaround takes around 2–3 hours."
- "Seriousness level: 8/10."
- "I still would not use a separate solution."
- "I prefer free tools."
- "Ideal solution: better understanding of the question — if the tool does not understand, it should ask again."

Most Surprising Thing:
Even though the user rated the issue as 8/10, they still did not want another tool. They preferred improving the existing interaction instead of adding more software.

What It Changed About My Design:
I originally assumed users always want a new solution for painful problems. This interview changed my thinking: users may prefer smarter clarification, fewer misunderstandings, and better communication inside existing tools rather than adopting another platform.
